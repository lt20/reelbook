# L19 — Instant start (E9)

iOS closes PWAs in the background: cold starts are the norm. Today the service worker goes to the network first with
no timeout, then 5 requests run one after the other before anything shows, and every signed image URL changes at each
start (no HTTP cache hit).

- Service worker: app shell **stale-while-revalidate** (serve the cache at once, refresh in the background; a new
  version is used on the next start — show nothing, no prompt). `index.html` included. Keep the versioned module URLs
  and `VERSION` (pitfall in COORDINATION).
- Last catalogue (themes, sheets metadata, sessions, notes index, practice last-done) saved per user in IndexedDB after
  each successful load, shown immediately at start, then replaced by the fresh load. Cleared on sign-out.
- Catalogue requests in parallel (`Promise.all`) where they do not depend on each other.
- Signed image URLs: the service worker caches `…/storage/v1/object/sign/…` responses **cache-first keyed by the path
  without the token**, at most ~300 entries (oldest out), so photos show offline and on a cold start without network.
  Sign-out clears that cache.
- Fonts: self-host the two families used (woff2, latin subset) under `app/fonts/`, add them to the shell; remove the
  Google Fonts link (also a privacy plus). Check licences (OFL) and add their files.
- Measure: time to first card on a cold start with the network throttled (Playwright CDP « Slow 3G ») before/after,
  in the report.
