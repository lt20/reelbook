# L0 — Agent tooling: Codex scripts, preview with a fake backend, iPhone screenshots

Why: the Paul protocol replaces the human test by (1) a second model's review of every PR and (2) screenshots of the
real app in an iPhone viewport. Reelbook has neither. Everything here is local tooling: nothing ships in `app/`.

## 1. Codex scripts (port from `~/dev/protocole/kit/scripts`, adapted)
- Port `codex-review.sh`, `codex-acceptance.sh`, `lib/codex.sh`, `lib/codex.mjs`, `codex/*.prompt.md`,
  `codex/*.schema.json` into `scripts/`. Keep every safeguard (ChatGPT login only, key variables removed, read-only
  sandbox, JSON schema, 3-pass stop rule, head-sha marker, exit codes).
- Adapt the prompts to Reelbook: static PWA, one `app/index.html` (CSS + HTML + JS), `app/sessions.js` (pure helpers
  `RS`), Supabase backend with RLS « own rows », Python CLI `tools/rb.py`, Claude skill `skill/reelbook/SKILL.md`.
  Tests: `node --test tests/*.cjs` (the app script run in a `vm` with a fake DOM, see `tests/auth-flow.test.cjs`)
  and `python3 -I tests/rb-*.py`. Protected zones (extra question « what happens to existing data and users at
  deploy? »): `supabase/**`, `.github/**`, `app/config.js`, `app/install.sh`, `app/install.ps1`, `tools/rb.py`.
- `codex-acceptance.sh <spec.md> --out <dir> [--commit]`: acceptance tests must be `node:test` files that reuse the
  harness of `tests/auth-flow.test.cjs` (factor its `app()` helper into `tests/harness.cjs` if needed, without
  changing what the existing tests assert) or pure tests on `app/sessions.js`.
- Port the kit's own tests that cover these scripts (`codex*.test.mjs`) when they run without Paul specifics; they run

## 2. Preview with a fake backend (`tools/preview/`)
- `tools/preview/build.sh <out-dir> [--work <dir>]`: copies `app/` to `<out-dir>`, replaces `vendor/supabase.js` by a
  fake client and adds `vendor/fake-data.js` (script tag injected before supabase.js), empties `sw.js`.
- Fake client: start from `/private/tmp/claude-501/-Users-laurentthevin-dev-reelbook/1a1f9232-fc0e-4b55-8c5f-59a2d02906d3/scratchpad/preview/vendor/supabase.js`
  (query builder: select/order/limit/eq/neq/single/maybeSingle/insert/upsert/update/delete, auth, signed URLs → local
  files, `?noauth` shows the sign-in screen). Add: `in`, `gte`, `lte`, `is`, `rpc` stub, a way to simulate a missing
  table (`?missing=sessions,practice_log` answers PostgREST error `PGRST205` / status 404 like Supabase), and writes
  kept in memory.
- Default data: **synthetic fixtures committed in `tests/fixtures/preview/`** (3 notebooks, ~8 sheets built from
  `templates/sheet.html` / `templates/exercise.html` with plausible French content, 2 video sessions with items and
  doses, one note, 3 requests: queued, processing, error with a reason). Images: small generated JPEGs (plain colour +
  label, made with Pillow by a script in `tools/preview/`, committed, < 20 KB each). **No frame from any real video.**
- `--work <dir>`: build the data from Laurent's local `work/` folder instead (never committed). Reference
  implementation: `/private/tmp/claude-501/-Users-laurentthevin-dev-reelbook/1a1f9232-fc0e-4b55-8c5f-59a2d02906d3/scratchpad/coord/preview-data-from-work.py`.
- `tools/preview/serve.sh <out-dir> <port>`: `python3 -m http.server` bound to 127.0.0.1.

## 3. iPhone screenshots (`tests/e2e/`)
- `tools/e2e-setup.sh`: installs `playwright@1.63.0` once into `~/.cache/reelbook-e2e` (browsers already cached on
  this Mac); no `package.json` at the repo root.
- `tests/e2e/shots.mjs --base <url> --out <dir> [--dark] [--steps <file.json>]`: iPhone 14 context; each step =
  `{name, hash?, query?, actions?: [{click|fill|press|wait|scroll}], full?}`, **fresh page per step** (dialogs and
  state must not leak between steps); exits non-zero on any `pageerror` or console error; writes
  `<out>/<name>.png` and a `report.json`.
- `tests/e2e/steps/smoke.json`: sign-in screen, home, a notebook, a sheet, a session, settings, add-video dialog,
  in light and dark.
- `tests/e2e/README.md`: how a lot agent builds, serves and shoots its worktree on its own port.

## 4. Journal
- `progress/README.md`: one file per lot `progress/YYYY-MM-DD-<lot>.md`, front matter `lot`, `pr`, `items`,
  `test` (commands actually run), `e2e` (steps file + verdict), `codex` (verdict + sha); body: what, why, decisions,
  pitfalls. No checker script.
