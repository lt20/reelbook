# L14 — Full-text search (E4) — protected zone (`supabase/schema.sql`, `tools/rb.py`)

Today search reads titles, summaries, groups, notebooks and authors only: « tapis » finds 0 sheets, 39 in the body.

## Schema (appended, idempotent, additive)
- `alter table public.sheets add column if not exists search_text text not null default ''`.
- `db push` by Laurent (decision 3). The app tolerates the column missing (select falls back to today's columns,
  no error).

## Writing it
- `tools/rb.py publish`: computes `search_text` from the sheet HTML: visible text only (strip tags, scripts, styles),
  plus kit pills; whitespace collapsed; capped at 4 000 characters. Tested.
- `tools/rb.py backfill-search [--dry-run]`: for every sheet of the signed-in account with an empty `search_text`,
  reads its `html` and writes `search_text`. **Laurent runs it** (decision 5); the agent never runs it against a
  backend. Unit-tested with a fake HTTP layer like the other `rb.py` tests.

## App
- Catalogue selects `search_text` when available. Search matches: titles, summaries, groups, notebooks, authors,
  `search_text`, and the user's notes bodies (load `notes.body` with the index already loaded, if cheap; otherwise on
  first search).
- Matching is accent- and case-insensitive and **at word start** (« dos » no longer matches « abdos »).
- Results show where it matched (« in the sheet », « in your note ») under the title.
- Empty state: « Nothing matches « x ». Try a body part or a piece of kit. »
