# L32 — Beta locks 2, 3, 4 and the waiting list in the database (decisions 15, 20) — protected zone (schema)

The hosted backend is Laurent's Supabase project (Pro plan, spend cap checked by Laurent). L29 bounds one account;
this lot bounds the whole project, so a successful beta cannot run up a bill. Additive migration in
`supabase/schema.sql`, idempotent like the rest of the file. **No `db push`, no read of production.**

## Own backends are not affected
`schema.sql` also runs on self-hosted projects. Every project-wide lock is **off until a settings row enables it**:
without the row, sign-ups, captures and uploads behave exactly as today. The PR body gives Laurent the SQL to run
on the hosted project, in order, including the row with his values.

## Settings (one row)
Table `beta_settings` (single row, `id boolean primary key default true check (id)`):
- `seats_total int` (50), `seats_offset int` (14: counted as taken from the start, inside the 50 — decision 15,
  applied by default), `signups_per_day int` (10),
- `max_photos_gb int` (10), `max_videos_per_day int` (300),
- kill switches `signups_open bool`, `captures_open bool`, `uploads_open bool` (lock 4, all true by default),
- `updated_at`.
RLS on, no policy for `anon`/`authenticated` (read through the functions below only). Laurent edits it in the SQL
editor or the table editor.

## Lock 2 — seats and sign-ups per day
- Trigger `before insert on auth.users` (security definer, `search_path = ''`): when the row exists, refuse when
  `signups_open` is false, when `seats_offset + count(auth.users not exempt) >= seats_total`, or when today's
  sign-ups (UTC) reach `signups_per_day`. Error `beta: full` / `beta: closed today` / `beta: closed` (errcode
  P0001), which the client maps to its own message (L31).
- Exempt accounts: the accounts with an `account_quotas` row whose `note` starts with `exempt` are not counted, so
  Laurent's own account does not take a seat. Document it in the SQL comments.
- One sign-up at a time: advisory lock, as in L29.
- **Check before writing it**: Supabase supports triggers on `auth.users`; confirm in the Supabase docs (search
  tool) that a `raise` in a before-insert trigger surfaces to `auth.signUp` as an error the client can read (often
  « Database error saving new user »). If the message is lost, the app relies on `beta_seats()` before sign-up and
  shows the generic refusal; say so in the PR.
- Public function `beta_seats()` (anon allowed, stable): `{taken, total, open}` with `taken = offset + real count`,
  or null when there is no settings row (the app then hides the counter). Never returns emails or ids.

## Lock 3 — project-wide caps
- In the existing `enforce_request_quota` path (or a second trigger on `requests`): refuse when the project has
  `max_videos_per_day` links today (`beta: project limit, try tomorrow`) or `captures_open` is false.
- In `photo_quota_ok`: refuse when the bucket total reaches `max_photos_gb` or `uploads_open` is false.
- Exempt accounts (above) pass. Without the settings row nothing changes.

## Waiting list (decision 20)
- Table `beta_waitlist (id bigint identity, first_name text not null check 1–60 chars, email citext/text not null
  check a basic shape and ≤ 254 chars, lang text check in ('fr','en'), consent_at timestamptz not null, created_at)`,
  unique on `lower(email)`. RLS on, **no policy**: nobody but the project owner reads it (dashboard, SQL editor).
- RPC `join_waitlist(first_name, email, lang, consent boolean)` (security definer, anon allowed): refuses without
  consent, refuses when seats are not full (the form is only for a full beta), caps at 200 new rows per day for the
  whole project (spam bound), and answers the same `ok` for a new email and an email already listed (no list
  probing).
- When someone signs up, the `auth.users` trigger deletes their row from `beta_waitlist` (same email) — the consent
  sentence promises it.
- For Laurent: in the PR body, how to read and export the list (Table editor › `beta_waitlist` › Export CSV, or one
  `select` in the SQL editor).
- `docs/privacy.md` (draft, not in force): add a short « Waiting list » paragraph (first name and email, only to say
  a seat is free, deleted at sign-up or on request). Marked to validate by Laurent.
