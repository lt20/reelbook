# L29 — Quotas on the hosted backend + privacy note draft (decisions 9 and 10) — protected zone (schema)

The hosted backend is Laurent's own Supabase project: any newcomer lands there with no limit. L25 and L26 send
newcomers to it, so they merge only once Laurent has pushed this lot's migration.

## Quotas (additive migration in `supabase/schema.sql`)
- Defaults per account: **10 video links per day** (`requests` inserted since midnight UTC), **300 sheets**
  (`sheets` rows, sessions not counted), **200 MB of photos** (sum of `storage.objects.metadata->>'size'` owned by the
  user in the sheets bucket).
- Table `account_quotas (user_id pk, max_requests_per_day int, max_sheets int, max_storage_mb int, note text)`:
  a row overrides the defaults for one account (null column = default). RLS: a user reads its own row, never writes.
  **Laurent's own account gets a row with high limits**: the lot gives him the one-line `insert` to run in the SQL
  editor with his user id (he finds it in Authentication › Users); the migration never guesses it.
- Enforcement in the database (a client cannot bypass it): `before insert` triggers on `requests` and `sheets`,
  and a storage insert policy; a clear error message (`quota: 10 links per day`, `quota: 300 sheets`,
  `quota: 200 MB of photos`). An update of an existing sheet (republish, redo) is never blocked by the sheet count.
- Function `my_quota()` (security definer, `auth.uid()` only) returns limits and current usage for the app.
- **What happens to current users at deploy**: Laurent's account must get its override row in the same SQL run,
  before any publish; the instructions put the `insert` right after the migration. Other existing accounts keep
  everything they have (limits only block new inserts).
- App: Settings shows « Usage: 4/10 links today · 120/300 sheets · 80/200 MB » when `my_quota()` exists (hidden
  otherwise); a refused link in the Add a video sheet shows the quota message instead of a generic error.
- `rb.py publish`: a quota error is reported in plain words (which limit, how to ask for more) and the queue item
  goes to `error` with that message.
- Own backends (self-hosted): the same schema applies; the README says how to lift the limits (one `insert`).
