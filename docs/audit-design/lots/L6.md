# L6 — Practice log (B1) — protected zone (`supabase/schema.sql`)

Why: the app counts what was saved, never what was practised; notes are already used as a training log (« 12 kg,
3x10 ok ») but one upsert overwrites the previous one.

## Schema (appended to `supabase/schema.sql`, idempotent, like the `sessions` block)
```
practice_log (
  id uuid pk default gen_random_uuid(),
  user_id uuid not null default auth.uid() references auth.users on delete cascade,
  slug text not null,                 -- a sheet slug, or 'session/<slug>' (same key as RS.noteKey)
  done_on date not null default current_date,
  text text not null default '',
  created_at timestamptz not null default now()
)
index (user_id, slug, done_on desc); RLS « own rows » for all, like the others.
```
`db push` to the hosted project is Laurent's (decision 3). README's self-hosting section says to re-run the schema.

## App
- **Tolerates a backend without the table** (`RS.missingTable`, as for `sessions`): every practice control and count
  is hidden, no error shown. The app is merged and deployed before Laurent pushes the schema.
- Catalogue: load `slug, done_on` of the user's rows (latest per slug kept client-side).
- Sheet and session pages, under the title: a button « Done today ». Tapping opens an inline row: a one-line text
  field prefilled with the last entry's text, and « Save ». Saved → the button reads « Done today ✓ » and a line
  « Last time: 28 Oct — 12 kg, 3x10 ». A second entry the same day is allowed (two rows).
- In « My notes », a « Log » list of the last 5 entries (date + text), newest first; the Log includes the latest entry, also shown as « Last time ».
- Cards: a meta « done 28 Oct » (latest entry) for sheets and sessions.
- Home counter: « 23 practised · 107 saved » (distinct practised slugs that still exist / sheets) replaces
  « 107 sheets »; the rest of the line stays.
