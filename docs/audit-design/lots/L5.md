# L5 — Session navigation and notes autosave (Q5 Q2)

## Q5 — Moving through a session
Today an exercise opened from a session page loses the session: the back link goes to the notebook, there is no
previous / next, and the dose is only on the session page card. 45 % of item doses are empty although the session
format gives a common dose.
- Exercise cards on a session page link to `#session/<slug>/<n>` (`n` 1-based over the items whose sheet exists).
  That route renders the sheet page with, on top, a banner « 2/4 · <dose> » (dose omitted when empty), a back link
  « ← <session title> » to `#session/<slug>`, and at the bottom two buttons ≥ 56 px: « ← Previous » and
  « Next: <next title> → » (first / last item: the missing one is absent; the last shows « Back to the session »).
- Reloading `#session/<slug>/<n>` keeps the banner. An out-of-range `n` opens the session page. A plain `#<sheet>`
  link renders as today. `RS.sessionSlugOf` and friends in `app/sessions.js` handle the new form, with tests.
- Keep the « Keep screen on » state (L3) across previous / next.
- Top bar of a sheet: the group label (« BACK ») reads like a back button; render it in normal case, muted, prefixed:
  « Group · Back ».
- Skill: in `skill/reelbook/SKILL.md`, when a session's format states one dose for every exercise, copy it into
  each `items[].dose` (still editable).

## Q2 — Notes save themselves
- « My notes » (sheet and session) saves 800 ms after the last keystroke, and immediately on `visibilitychange` to
  hidden, `pagehide` and route change. Status text: « Saving… » / « Saved » / on error « Not saved » + a « Retry »
  button. The « Save » button goes away. Nothing is written when the text did not change.
