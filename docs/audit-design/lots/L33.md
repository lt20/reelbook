# L33 — Daily ntfy alert sent by the database (decision 17) — protected zone (schema)

After L32 merged (same file). Additive SQL in `supabase/schema.sql`, **in a section that only runs when
`pg_cron` and `pg_net` are enabled** (own backends without them must still run the whole file): guard with a
`do $$ … if exists (select 1 from pg_extension where extname = 'pg_cron') …` block, and say in the PR body that
Laurent enables the two extensions first (Dashboard › Database › Extensions).

## What
- One job per day, 08:00 Europe/Zurich (expressed in UTC). Daily only, no immediate alert.
- Message, one line every day (proof the job lives): seats `taken/total`, today's sign-ups, photos `GB / max`,
  videos today `/ max`, waiting-list size and new entries since yesterday. A « 70 % » tag when any figure is
  ≥ 70 %, priority high when any is ≥ 90 %.
- The ntfy topic is stored out of reach of clients: in `vault` if available, else a column of `beta_settings`
  (no policy, so clients never read it). Never in the repo, never in the PR body: Laurent pastes it in the SQL
  editor himself (placeholder `<your topic>`).
- No email address and no first name in the message (counts only).

## DoD
Static tests (guarded section, job name, no topic in the file, no personal data in the message), the whole
`schema.sql` still runs without the extensions (local Postgres if available). PR body: steps for Laurent and a
business test (run the job's function once by hand, the notification arrives). Codex `ok`, protected variant.
