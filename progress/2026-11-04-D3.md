## What
- `scripts/codex-acceptance.sh --out` must name a folder strictly under `tests/`, checked on the physical path (nearest
  existing ancestor resolved with `pwd -P`, plus the segments still to create) before anything is created or Codex is
  called, and again after `mkdir`. A link under `tests/` that points elsewhere in the repo is refused too.
- `tests/e2e/shots.mjs` runs in WebKit by default (iPhone 14 profile), `--browser chromium` kept; `report.json` names
  the browser. `tools/e2e-setup.sh` installs WebKit and Chromium. A browser missing from Playwright's cache stops the
  run (exit 2) with a message pointing to `tools/e2e-setup.sh`.
- `tests/e2e/nav-check.mjs`: five browser checks on the preview (scroll restored on Back from a sheet, browser and app
  button; « Discard your changes? » on leaving a changed session edit, Cancel keeps / OK leaves, none for an unchanged
  edit; Back/Forward through two L23 facets). Run by hand; command in `tests/e2e/README.md`.

## Why
COORDINATION « Debt »: `--out` of L0 accepted any folder of the repo; screenshots in Chromium while the app's users are
on iOS Safari (WebKit installed on the Mac since L20); L17's `check.cjs` lived outside the repo (#47).

## Decisions
- `tests/` itself is refused as `--out` (acceptance tests go to `tests/acceptance/<lot>`).
- `launchBrowser` / `loadPlaywright` are exported by `shots.mjs` and reused by `nav-check.mjs` (no third file).
- `nav-check.mjs` compares the links of the visible result cards, in order (the search grid keeps hidden cards when no
  facet is chosen).
- It tolerates the known `img/thumb.jpg` 404 (the same `allow` as the steps files) and a photo request the browser
  cancels when the page moves on (WebKit `cancelled`, Chromium `net::ERR_ABORTED`); any other failed request fails.
- The duplicate debt line « Screenshots run in Chromium, not WebKit (L0) » is struck with the WebKit one.

## Pitfalls
- The worktree guard refuses a `node`/`sed` with a variable argument in a loop: plain commands, one per file.
- `page.goBack()` on a hash entry that `window.confirm` cancels: the app moves forward again itself (`undoLeave`), so
  the check waits for the session hash rather than for a navigation.
