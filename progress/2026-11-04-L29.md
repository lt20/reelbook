## What
- Each account of a shared backend is limited: 10 video links a day (UTC), 300 sheets, 200 MB of photos. The
  database enforces it (triggers on `requests` and `sheets`, the storage insert/update policies); a row of
  `account_quotas` lifts it for one account. Nothing stored is touched; republishing an existing sheet always works.
- Settings: « Usage: 4/10 links today · 120/300 sheets · 80/200 MB » when the backend has `my_quota()`.
- Add a video (and « Something wrong? »): a refused link says « Limit reached: 10 links per day on this backend… ».
- `rb.py publish <dir> [--request <id>]`: a quota refusal names the limit, what to do and how to ask for more; with
  `--request` the queue item goes to error with that message. The skill passes `--request`.
- README « Limits on a shared backend » (the one insert that lifts them), own-supabase and hosted docs.
- `docs/privacy.md`: draft, not in force, placeholders, linked from nowhere.

## Decisions
- Sheets counted = every row of `public.sheets` (old one-page sessions included, so `kind` cannot be used to dodge
  the count); the `sessions` table is not counted (spec).
- Links counted = rows of today (UTC) still present; `created_at` is forced to the server clock on insert and frozen
  on update. Deleting a link of today frees its slot (the limit bounds what is stored).
- Photos: the policy cannot see the size of the file on its way, so the account is refused once its files reach the
  limit (the last upload may pass it by one file, at most 5 MB). One account's checks are serialized (advisory lock,
  volatile function). Overwrites (`x-upsert`) are checked too, so a full account cannot grow by overwriting small
  files with big ones; `rb.py publish` no longer sends a photo the backend already holds (same MD5 as its eTag), so a
  republish with the same photos writes nothing to storage and is never refused (Codex pass 1).
- `rb.py publish` reads `my_quota()` before sending anything (new sheet past the sheet limit, new photos on a full
  account: stop, nothing sent) and removes the photos it had added if the database still refuses midway (a race).
  The read is made by the callers (`cmd_publish`, `_publish_session`) and passed to `_publish_sheet`: the L14
  acceptance test pins `_publish_sheet` to a single `POST sheets`.
- A session checks that all its new sheets fit before publishing the first one (Codex pass 2).
- `rb.py requeue-sessions`: a batch refused by the daily link quota is queued one by one until the limit; run it
  again tomorrow for the rest (Codex pass 1).
- Quota checks run for every writer, service role included (an Edge Function inserting on behalf of a user, L28,
  stays limited).
- The functions raise `P0001 quota: …` so that PostgREST and the app read the limit; rb.py falls back to
  `my_quota()` when the storage server hides the message.

## Pitfalls
- `rb-*.test.py` files are not found by `unittest discover` (dash): run each file. CI lists them one by one in
  `.github/workflows/ci.yml` (Laurent's zone): `tests/rb-quota.test.py` is not in it yet.
- The worktree sandbox refuses long chained Bash commands: write edit scripts to the scratchpad and run them.
- PGlite (`npm i @electric-sql/pglite` in the scratchpad) runs the schema without Docker: stub `auth.uid()` on
  `request.jwt.claim.sub`, `storage.objects`, `storage.foldername`, and the roles `anon` / `authenticated`.
