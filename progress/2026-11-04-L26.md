## What
- `install.sh` without `--url/--key` (and `install.ps1` without `REELBOOK_URL/REELBOOK_KEY`) signs in to the hosted
  backend: `hosted.url` and `hosted.anonKey` are read from `https://lt20.github.io/reelbook/config.js` as text (never
  run), checked (https origin; JWT or `sb_publishable_` key), with a clear message when the file cannot be read or
  holds no valid hosted backend. With arguments: unchanged. The backend is resolved before anything is installed.
- New: `install.sh --help`, `--dry-run` (shows the backend, folder, then stops); `install.ps1`: `REELBOOK_DRY_RUN=1`.
  `REELBOOK_CONFIG_URL` reads another config.js (a fork, a `file://` copy: what the tests use).
- Settings and the welcome guide: on the hosted backend the lines are `curl -fsSL <app>/install.sh | bash` and
  `irm <app>/install.ps1 | iex`; on an own backend they keep the url and key. « Send to my computer »: Web Share of
  the two lines plus one sentence; without it (or when sharing fails, not when closed) a `mailto:` to the signed-in
  address with the same text.
- README Quick start and `docs/manual-install.md` updated.

## Why
Audit O2: the install line carried the backend url and key, long and different for everyone, painful to get from a
phone to a computer.

## Decisions
- Half a backend (`--url` without `--key`) is now an error (it used to skip the sign-in silently).
- Both lines (macOS/Linux and Windows) are sent: the phone does not know the computer's system.
- The mail goes to the signed-in address (sending to oneself).
- `install.ps1` runs its steps inside a function: under `irm | iex`, a dry run returns without closing the window.

## Pitfalls
- `pwsh` is not installed here: `install.ps1` is checked statically (same regexes as `install.sh`, no
  `Invoke-Expression` of the downloaded text); the pwsh dry-run test runs where pwsh exists.
- The harness now returns `location` (to read a `mailto:` set on `location.href`).
