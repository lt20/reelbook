## What
- **Step A (app only).** Add a video has a « Paste link » button: it reads the clipboard, fills the field with the
  first supported link it finds (Instagram, TikTok, YouTube, Facebook), and otherwise says why (empty clipboard, no
  supported link, clipboard not readable). The floating + opening an empty form tries the clipboard too (permission
  permitting; on iOS the system's Paste bubble) and fills the field silently, never sending it: Queue it is still
  the only way to queue. A link left unqueued (rb.draft) is never replaced.
- **Step B (needs Laurent's deploy).** Settings › « iPhone shortcut »: make a key (a label), copy it once (shown as
  the `Authorization` value, `Bearer rb_…`), revoke it; the steps to build the shortcut (Share Sheet → Get URLs →
  Get contents of URL, POST). Table `capture_tokens` (hashed keys, RLS own rows, column grants, one active key per
  account, a revoked key stays revoked) and Edge Function `add-link` (POST, Bearer key looked up by SHA-256 with the
  service role, 10 links a minute per key, the app's link check, a normal `requests` insert so the quota trigger
  applies, its message sent back as is). The section stays hidden until the table exists.

## Why
O5: saving a video took copy, open Reelbook, +, paste. iOS has no Web Share Target for PWAs: a shortcut in the Share
Sheet is the one-gesture path.

## Decisions
- One active key per account (partial unique index): the acceptance tests drive a single Revoke button, and
  shortcuts sync across a user's Apple devices through iCloud. No hidden live key can exist.
- The rate limit lives in the row (`window_start`, `window_count`, fixed window, compare-and-set): Edge Function
  isolates share no memory.
- Answers are one line of plain text, for Show Notification in the shortcut.
- Paste link right after + (within 2 s) uses the read + started instead of asking iOS twice (and the acceptance test
  counts one read); a failed read is never reused.
- Revoke has no confirmation step (the acceptance test revokes in one tap): À confirmer.
- Harness: `crypto` (Node's Web Crypto) added to the app's vm context, as every browser has it; the app needs
  `crypto.getRandomValues` and `crypto.subtle` for the key (no Math.random fallback for a secret).

## Pitfalls
- CI has no Deno: the two Deno cases of `tests/acceptance/l28/capture-backend.test.cjs` fail there (ENOENT) until
  `.github/workflows/ci.yml` installs it (`denoland/setup-deno@v2`) — Laurent's zone. `tests/add-link.test.cjs`
  skips with a reason when Deno is absent.
- `tests/quota-schema.test.cjs` reads schema.sql from the L29 header to the end: the L28 section is written before
  the quotas section, not appended.
- `deno eval --no-remote` imports core.ts: it must import nothing; index.ts carries the `npm:` import.
- The worktree sandbox refuses chained or heredoc-to-file commands: write scripts to the scratchpad, run them alone.
