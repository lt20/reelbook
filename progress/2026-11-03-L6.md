## What
- `supabase/schema.sql`: `practice_log` (id, user_id, slug, done_on, text, created_at), index
  `(user_id, slug, done_on desc)`, RLS « own practice log ». Additive, idempotent, like the `sessions` block.
- Sheet and session pages, under the title: « Done today ». Tapping it opens a one-line field prefilled with the
  last entry's text, plus Save. Once saved, the button reads « Done today ✓ » (green) and a line
  « Last time: 28 Oct — 12 kg, 3x10 » shows. A second entry the same day adds a second row. A failed save keeps the
  text in place with « Not saved. Try again. ».
- « My notes »: a « Log » with the last 5 entries (date + text), newest first.
- Cards (sheets, sessions, exercise cards in a session): « done 28 Oct ».
- Home: « 3 practised · 9 saved · 2 sessions · 3 notebooks ».
- With no table (`?missing=practice_log`), or when the read fails: none of it shows and no error appears. The page
  is the same as before L6.

## Why
B1: the app counted what was saved, never what was practised. Notes were being used as a training log, and each
upsert overwrote the one before.

## Decisions
- `done_on` is sent by the app as the device's calendar day: `current_date` on the server is the UTC day, which
  would be wrong between midnight and 1 or 2 am in Geneva. A `YYYY-MM-DD` is shown as a local date.
- The ✓ shows while the latest entry is from today, so reopening the page the same day still shows it.
- Catalogue: reads `slug, done_on` (1 000 rows a page, PostgREST's cap) and keeps the latest per key. Each page
  then reads its own last 5 entries (`id, slug, done_on, text, created_at`).
- Placement: right after the sheet's `<header>` when its `<h1>` sits inside one, otherwise right after the `<h1>`.
  A sheet without an `<h1>` gets one from the catalogue title (needed by the acceptance test, whose sheets have no
  html).
- In place repaint: the practice block and the Log are two regions ending with a marker comment. In a browser only
  those regions are rewritten, so the sheet, its photos and the note are left alone. In the vm harness, which has
  no `querySelector`, the page's markup string is edited, following the same `view.querySelector ?` guard as
  `renderRows`.
- One entry is limited to 200 characters. The Log is hidden when there is no entry yet.
- `tests/auth-flow.test.cjs`: the v1-sessions test now expects the new home line (its tables have an empty
  practice log).

## Pitfalls
- The acceptance test for the Log counts every `entry-N` in `#view`. « Last time » repeats the newest entry, so the
  test cannot pass while the spec is followed (Open question in COORDINATION.md).
- The harness's DOMParser keeps only `<a>` links, so where the block lands in a real sheet (after `</header>`) is
  checked in the screenshots, not in node tests.
- Compare objects from the vm realm after a JSON round-trip (`deepEqual` checks prototypes).
