## What
- The app opens on its last catalogue at once (IndexedDB, per backend and user), then the fresh read replaces it;
  if the read fails (offline, backend down), the cached catalogue stays. Sign-out drops it.
- The service worker serves the shell from its cache and refreshes it in the background (stale-while-revalidate,
  `index.html` included): a new version shows on the next start, no prompt. Uncached files go to the network.
- Signed photos (`/storage/v1/object/sign/…`) are cached by the service worker, cache-first, keyed by their path
  without the token, 300 at most (oldest out), and cleared on sign-out (`CLEAR_USER_CACHE`).
- The catalogue reads (themes, sheets, sessions, notes index, practice log) run in parallel.
- A sheet opened once is kept, so it opens offline with its photos.
- Barlow Condensed (600, 700) and Source Sans 3 (400–600, variable) are self-hosted in `app/fonts/` (woff2, Google
  Fonts latin subset: French accents, « », œ), with their OFL files; the Google Fonts link is gone.

## Measured (Playwright, iPhone viewport, fake backend; scratchpad `L19/measure/*.json`)

## Decisions
- The pure logic is in `app/sessions.js` (`catalogueSnapshot`, `restoreCatalogueSnapshot`, `catalogueCacheKey`,
  `refreshCatalogue` with storage and network injected), as the acceptance tests ask; `sessions.js?v=7`,
  `rb-shell-27` (after L9 took v=6 / 26).
- Cache key `rb.catalogue.<user id>.<backend url>` (decision 8, plus the backend); a sheet is
  `<that key>|sheet|<slug>`, so the sign-out prefix `rb.catalogue.<user id>.` drops both.
- The snapshot keeps the signed URLs of the cards (expired or not): the worker answers a photo by its path.
- A cached catalogue on screen when the fresh read fails: no error line (console only). À confirmer.
- When the cache is on screen, the fresh read redraws the home page in place (no scroll jump) and leaves an open
  sheet alone (notes being typed).
- Expired token: supabase-js refreshes it over the network before `INITIAL_SESSION` (after an hour away, the usual
  iOS cold start). With a session stored for the backend and a cached catalogue, the home page shows from the cache
  at once; the network read waits for supabase-js to confirm the user (an unconfirmed read would go out with the
  anon key and RLS would answer empty lists). Offline (no session, but still stored) the cached view stays.
- Photos are fetched by the worker in CORS mode (Supabase Storage sends `Access-Control-Allow-Origin: *`), so the
  cached copy is not opaque (Chrome counts an opaque response as ~7 MB of quota); a storage without CORS still gets
  its photo, uncached.

- Codex pass 1: photo URLs carry their sheet's `updated_at` (`rbv`, kept in the worker's key, only `token` is
  stripped), so a sheet republished under the same photo paths gets its new photos; a sign-out bumps an epoch in
  the worker so a photo still downloading is not put back; deleting a sheet or a session, or adding a notebook,
  saves the cached catalogue again (and drops the sheet's kept page), so a start without network does not bring
  it back.

- Codex pass 2: a notes or practice log read that fails keeps what was known (a backend without `practice_log`
  still hides it); a note saved or a practice logged saves the cached catalogue; a kept sheet read across a
  sign-out is dropped.

- Codex pass 3 (fixed after the last pass): deleting a sheet drops its photos from the worker (`DROP_PHOTOS`
  `<user id>/<slug>/`); a switch from one account straight to another clears the first one's cache too. Its
  remark (no offline hint when the cache stays on screen) is left under À confirmer.

- Arbitrage passe 4 (coordinator, two fixes): (1) a catalogue read overtaken by a local change (sheet deleted,
  moved, session created / edited / deleted, notebook added / removed, practice logged, a note that appears or
  empties) is neither applied nor saved: `localGen` (bumped before the write goes out and in `saveCatalogue`),
  `RS.refreshCatalogue({gen})` reads again once, overtaken twice it keeps what is shown (`source: 'local'`, saved);
  the cached copy is not applied after a local change either. Moves now save the cached catalogue; deletes filter
  by slug. Regression test in `tests/auth-flow.test.cjs` (harness: `idb`, `hold`). (2) `rbv` never reaches
  Storage: the worker fetches the signed URL without it (its fallback too, page's mode kept), the cache key keeps
  it; the app adds it only under a controlling worker. `VERSION` rb-shell-28. DoD: `node --check app/*.js`,
  `node --test tests/*.cjs tests/acceptance/*/*.test.cjs scripts/tests/*.test.mjs` 234/234, smoke 8/8 (port 8789).
- Merge of main after L10 (#39): both sides kept; `sessions.js?v=8` (both had moved to v7), `sheet.js?v=2`,
  `VERSION` rb-shell-29, SHELL = versioned modules + fonts + icons. With every read at once, a failed sessions
  read had dropped the sheets too (L10 acceptance « does not strand the player »): it now keeps the sessions
  known, applies the sheets and reports the error as before L19. DoD 254/254, smoke 8/8, `steps/l10.json` 7/7,
  player opened on a restart from the cached catalogue (`#session/<slug>/play/2`, scratchpad script).
- Codex pass 5 (forced): bloquant, two races. Arbitrage passe 5 (coordinator): (a) `DROP_PHOTOS` bumps the
  worker's `epoch`, so a deleted sheet's photo still downloading is not put back in the cache; (b) deleting a
  sheet captures the client and the user id, and stops after each await if either changed (nothing removed from
  the catalogue shown, nothing saved). One regression test each (`tests/sw-photos.test.cjs`,
  `tests/auth-flow.test.cjs`, harness: `authListener`, `hold` on writes too), both failing without the fix.
  `VERSION` rb-shell-30. DoD 256/256, smoke 8/8, `steps/l10.json` 7/7. No further Codex pass (coordinator).

## Pitfalls
- The preview (`tools/preview/build.sh`) empties `sw.js` and its fake backend never touches the network: the
  measurements patch a copy in the scratchpad (`L19/tools/patch-preview.py`), nothing in the repo.
- `readPractice` already existed (notes field); the practice log read is now `readLastDone`.
- Opened sheets are kept without a limit (a few KB each), cleared on sign-out.
