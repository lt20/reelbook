## What
`#demo` (or `?demo`) opens a read-only notebook from `app/demo/`: banner « Demo · read only · Create an account »,
home (session + sheets by notebook), sheet pages with the real sheet CSS and `sheet.js` order, the session page.
« See a demo » on the sign-in screen. Placeholder content: 4 drawn sheets (3 gym, 1 kitesurf technique) and 1 session.

## Why
O3: a visitor could not see what a sheet looks like without installing Claude Code and processing a video.

## Decisions
- Separate `#demo` view rendered by its own small renderer (reuses `card`, `nbIcon`, `sheetLang`, `RBSheet.arrange`)
  rather than feeding demo data into the real catalogue: the real pages read Supabase (notes, practice, signed URLs).
- `boot` creates no Supabase client while the hash is `#demo…`; `route` starts the remembered backend when leaving.
- Leaving the demo in sign-in mode repaints the sign-in screen (`setMode('in')`), so the title is « Sign in ».
- Offline: the app fetches all demo files on the first visit; the SW's existing shell cache keeps them (no precache).
- Drawings: `scripts/demo-drawings.py` (SVG silhouettes); thumbnails are square 500×500 scenes, steps 400×500.
- Banner with an account kept on the device (`rb.auth.<backend>` session): « Back to my notebooks » (À confirmer).

## Pitfalls
- The harness has no `fetch`: an optional `fetch` was added to `tests/harness.cjs` for the demo's own tests.
- Playwright `wait` on a selector waits for visibility: `[hidden]` selectors time out.
- A first start on a device shows the welcome page after sign-in, not home (normal, not the demo's doing).
