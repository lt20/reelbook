## What
`docs/audit-design/mockups/p7-signup.html`: one static, clickable file (no CDN, fonts from `app/fonts` in relative
path) drawing every state of the auth screen and `#welcome`, FR and EN, light and dark, in a 390 px phone with a
« 664 keyboard » toggle. States are picked in the left column (or `?s=<state>&lang=en&theme=dark&kb=1`); the state
label, its description and « what the app knows » sit in the chrome, outside the phone. `window.__mk` exposes
`states`, `show`, `setLang`, `setTheme`, `setKb` for Playwright.

States: signup (empty, filled, sending, offline, check blocked, check refused, address already has an account),
code (waiting, typing, checking, wrong, expired, too many attempts, sent again with 60 s countdown, resend too soon,
offline, back from Mail, from sign-in with an unconfirmed address, confirmed), sign-in (empty, wrong, busy, offline),
forgot, reset (empty, wrong code), password changed (bare home), waiting list (full, consent ticked, closed, noted),
`#welcome` (brand-new account, computer linked).

## Why
P7-signup.md: the person never knew whether the account existed. Every screen carries a one-line status with a dot
(grey = no account, amber = pending, green = exists / created) under the main action, and the banner of `#welcome`
names the address the account was created for.

## Decisions
- One main action per screen: filled `.btn`; everything else is a link or `.btn.ghost`. On `code-expired` the main
  action becomes « Recevoir un nouveau code »; on `code-toomany` and when the check is blocked it is disabled.
- The code is one `one-time-code` numeric field (paste-friendly), not six boxes.
- `#welcome`: four steps (account, computer, phone, first video); the next undone step is outlined and holds the
  main action. On the phone the useful action for the computer step is « Envoyer à mon ordinateur » (the app's L26
  action), « Copier » is secondary. The phone step is a checkbox « C’est fait sur mon téléphone » plus « Ajouter le
  raccourci »; nothing is shown as done that the app does not know (L43).
- `exists` title: « Cette adresse a déjà un compte » (the app knows the address, not the person).
- Hosted path: « Serveur : » is gone; one line « Carnet hébergé chez Reelbook · Sur mon Supabase plutôt ».
- Real-person check drawn as a neutral frame with « Cloudflare » at the right (what the widget shows); no `captcha`
  word in FR.
- Guide text rebuilt from the landing's « Installer » and « Au quotidien » (data-k `inst.p`, `i2.*`, `i3.*`,
  `d1`–`d4`) plus `w.need3`, `w.run2`, `w.run4` of the current `#welcome`; no duration per sheet, no hour.

## Spec gaps (flagged, not invented)
- Forgot password: `/recover` does not say whether the address has an account (no enumeration), while decision 23
  reveals it on sign-up. The `reset` screen says « si un compte y est rattaché » and offers sign-up as the way out.
  To decide: accept, or probe existence first (an extra call, and it would make enumeration symmetrical).
- L43: « a computer is known once a sheet or a processed request exists » means the computer step can never be
  done before the first video is: in `welcome-pc` both are done. To decide: keep (and order the steps so), or add a
  trace of the computer's sign-in (`cli-login` / `rb.py login` writing a row) so the step turns green at install.
- `exists` relies on `identities: []` with confirmation on; with confirmation off (shipping order), the existing
  message of the app stays. The mockup draws one screen for both.
- Waiting list « closed » has no text in L31 beyond the refusal message; the mockup uses « La bêta est fermée pour
  l’instant / Inscriptions en pause ».

## Pitfalls
- WebKit caps `history.replaceState` at 100 per 10 s: the state switch wraps it in try/catch, or Playwright
  loops crash with a SecurityError.
- `--fs-display` is `12vw` of the page: pinned to 2.925rem (12vw at 390) on the phone so desktop viewing matches.
